## 13.0.0-alpha.1 (2026-10-01) — platform foundation (work in progress)

### English
- One plan for web, macOS, Windows and Linux (`docs/PLAN-UNIFIED-BG.md`); Codex's V12 work integrated after a file-by-file review.
- Fixes from the review: AI history keeps working after a restart; AI patches only touch the exact listed files, never rewrite text they saw redacted, and the engine (not the model) decides the risk; untrusted file content is fenced with per-request markers; secrets are removed from every model input. Downgrades keep paid credits; refunds follow the invoice lines; chargebacks suspend paid work without deleting sites; a failed payment has a 7-day grace from the failure. Setup cancels cleanly, verifies every tool it installs, never runs the macOS git stub, and only checks the hosts it needs.
- Credits V3: included AI credits are released over 14 days (they cannot run out earlier), 24-hour and 7-day safety limits only decide when a new task may start, packs are used outside the schedule, a one-time starter bonus covers creating the first site, and active sites no longer spend AI credits. New prices and plan contents; hosting is "connected" (you pay Netlify directly) until a Netlify agreement exists.
- The engine runs on macOS, Linux and Windows: per-OS folders, PATH, process handling, launchers, secure secret storage (Keychain, Secret Service or an encrypted file, Windows DPAPI — never plain text) and script isolation (sandbox-exec, bubblewrap).
- New shared design tokens and a web interface prototype (English first) for the web app and the new desktop shell (Tauri), with a Create-site flow, the assistant, activity and Plan & usage.

## 11.1.0-rc.1 (2026-09-30) — "Launchpad"

From a folder to a live, watched site with the fewest steps. Everything in 11.0.0-rc.1, plus:

### English
- **Site quality check** (roadmap WP10): a new check step reads the built pages and says whether the site is ready for visitors — page title and description, `<html lang>`, canonical and social preview, placeholder text and images, links to localhost, broken internal links and missing files, resources over http://, empty links, TODOs, images without alt text, form fields without labels, empty buttons, image and page budgets, and the launch files (404, robots.txt, sitemap.xml, favicon). Real problems block the release; recommendations warn; file hints never change the status but get a one-click safe fix (`site.robots`, `site.sitemap`, `site.404`) that writes into the folder the build ships. Per-project `bid.config.json` → `site.disable / severity / budgets`. Every finding is an issue with file, line and evidence; the AI can fix the page-level ones. Server-rendered sites are checked after deploy instead.
- **Launch checklist**: the project screen opens with folder → check → ready for visitors → hosting → live → own domain → watching, each step derived from what the engine knows, with the next action as a button (`bid launch`, also inside `status`). Disappears when everything required is done.
- **New site from a template** (roadmap WP19): "New site…" in the sidebar and the palette creates a folder from a curated static template (landing page or portfolio) with the site's name, language (Bulgarian or English), description, a privacy page, 404, robots, sitemap, favicon, social image, `netlify.toml`, `.gitignore`, a project config and one Git commit — and it passes the whole check on its first run (`bid new list | create`). Templates ship inside the engine bundle.
- Health grid gains the "Ready for visitors" tile; `exists` error code for `bid new`.
- **Pushover notifications**: "Connect Pushover…" in the monitoring card takes your user key and an application token, verifies them with Pushover and keeps them in the macOS Keychain (passed to the engine through the environment, never argv, masked in status). A confirmed incident arrives on the phone with high priority and a link to the site, a recovery with normal priority; "Send test" reaches every configured channel (webhook and Pushover); quiet hours and maintenance windows still apply. `bid monitor pushover connect | disconnect | status`, error code `pushover_rejected`.
- **Safety of files, scripts and publishing (WP01)**: one path policy for every AI file operation (read, create, edit, delete, undo) — `..` segments and absolute paths refused as written, no symlink anywhere on the way, writes with `O_NOFOLLOW`; secrets (`.env*`, keys, certificates) never enter a model context or an AI write; config files that decide what runs or gets published (package.json scripts, bundler/hosting configs, lockfiles) are shown as a diff but applied only with their own tick (`ai apply --allow-config`); a root file no longer lets the assistant create files anywhere; undo records are checked like any write. Project scripts (lint, typecheck, build, install, dev server) get an allowlisted environment — never the engine's secrets, `NODE_OPTIONS` or `npm_config_*` — and on macOS run in a sandbox without Keychain access or the engine's folders; the check reports `isolation`. The app's automatic check (`check --auto`) refuses scripts or build configs that changed since the user last started a check. Every static upload (Netlify, Cloudflare Pages, GitHub Pages) goes out from a private staged copy whose SHA-256 manifest must equal the check's or the release snapshot's, re-hashed after the upload; parallel jobs never share a folder. Endpoint overrides work only in the test suite (`BID_TEST_ENDPOINTS=1`) and never in the app bundle (`engine/.production`); a local cloud URL is refused in the bundle. Passwords, tokens and keys are refused as command-line flags (`secret_in_argv`); the preview stop token moved out of argv. No more `npx --yes netlify-cli / gh-pages` downloads. Error codes `scripts_changed`, `secret_in_argv`, `secret_file`.
- **Resilience (WP02)**: every network call of the engine has a deadline (`fetchT`, 20 s by default; AI streams 60 s to the first byte and an idle timeout of 120 s between bytes, so a silent provider ends as `ai_timeout`); the update DMG is streamed to disk and hashed on the way with a size cap and an idle timeout; `git commit` gets two minutes; a release promote on Vercel / Cloudflare / GitHub Pages is no longer refused by the 30-minute check age when its snapshot was just re-verified. The app: an engine call can time out and cancel is real (SIGTERM, SIGKILL five seconds later); a failed first load of Mission Control, Setup, Costs or Monitoring shows the reason with Retry instead of an endless placeholder; a failed account check is its own screen (Retry, continue offline) instead of a silent anonymous session; a broken engine is reported as such, not as "Node is fine"; "saved" appears only after the engine confirmed it; `--json` values are built with JSONSerialization; the menu bar says when the engine or Node is missing. The release dry run proves the shipped engine runs with only `/usr/bin:/bin` on PATH (bundled Node, production copy, no overrides).
- **Cloud data (WP03)**: retention runs inside the database in bounded batches (`bid_prune`, indexed; the old worker loop stopped at PostgREST's 1000 rows and never pruned the heartbeat) — probes 90 days, resolved incidents 90 days, heartbeat 7 days, AI usage 13 months, admin audit 24 months, open incidents never; one shared, atomic rate limiter in Postgres (`bid_rate_hit` under an advisory lock) for checkout, portal, sync, monitor test/register, export and admin writes (`rate_limited`); the data export pages past 1000 rows and includes monitoring targets, probes and incidents; the privacy page describes server-side monitoring and the real retention periods; an admin-only **Cloud readiness** card (`bid admin diagnostics`) says which secrets are set (yes/no only), whether the scheduler runs, which Paddle price ids and legal links are missing, and whether the schema has the new functions. Deno 86, RLS 10.
- **Feedback and accessibility (WP08, first part)**: "Send feedback…" in Settings builds the redacted support report, lists every file in it before anything leaves the Mac, and opens an e-mail to support that the user sends themselves; every clickable row and card (projects, Mission Control cards, domains, run steps, Netlify sites, file choices) is also a button for VoiceOver and Full Keyboard Access; ⌘5–⌘8 open Assistant, Plan & usage, Account and Admin; History and Refresh are off without a project; the unused production sheet and its strings are gone. The engine keeps its own files bounded: the costs ledger, assistant history, release records (newest 50 / 180 days), build manifests (newest 20), smoke logs and support reports (30 days).
- **Template gallery**: "New site…" now offers 20 designs in 7 categories — business, trades, coming soon, restaurant, hotel, beauty salon, clinic, gym, shop showcase, real estate, SaaS, mobile app, portfolio, CV, blog, link in bio, event, wedding, online course and nonprofit. Every template is written in Bulgarian and English (the site keeps only its language), has its own palette, realistic sample content, a contact/booking form (Netlify Forms), a social preview image, and passes the site quality check on the first run (tested for all 40 combinations). A proposal for credits V2 (site-months, 5-hour and weekly windows, upgrade/top-up nudges) is in `docs/PLANS-AND-CREDITS-V2-BG.md`.

- **Сигурност на файловете, скриптовете и публикуването (WP01)**: една политика за всяка файлова операция на AI (четене, създаване, редакция, изтриване, undo) — `..` и абсолютни пътища се отказват както са написани, без symlink по пътя, запис с `O_NOFOLLOW`; тайните (`.env*`, ключове, сертификати) никога не влизат в контекст на модел или в AI запис; конфигурациите, които решават какво се изпълнява или публикува (скриптове в package.json, bundler/хостинг конфигурации, lockfiles), се показват като diff, но се прилагат само с отделна отметка (`ai apply --allow-config`); файл в корена вече не позволява на асистента да създава файлове навсякъде; undo записите се проверяват като всеки запис. Пароли, токени и ключове не се приемат като флагове (`secret_in_argv`); stop token-ът на preview сървъра излезе от argv. Без `npx --yes netlify-cli / gh-pages`. ### English
- **Issues**: every finding of a check is one item with severity (blocker / high / medium / low / info), kind (confirmed defect / recommendation / heuristic signal), confidence, evidence (file:line, log), impact, the proposed fix with its risk and the steps that verify it. Runs on this Mac — the app's timer, or a launchd agent installed with your consent — and says so; there is no server-side monitoring yet.
