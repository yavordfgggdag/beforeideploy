# Облакът: защо входът не работи и как се довършва (за собственика)

Проверено на 2026-09-29 от GitHub runner (workflow `cloud-check`) срещу проекта, с който приложението е
пакетирано (`engine/cloud.json`, ref `rrnveotqvmsspmzaswlp`):

| Какво | Състояние | Ефект в приложението |
|---|---|---|
| Проектът отговаря (`/auth/v1/health`) | ✅ | — |
| Вход с имейл и парола, регистрация | ✅ включени | — |
| **Потвърждение на имейла** (`Confirm email`) | ⚠️ включено | Вграденият mailer на Supabase праща **само до имейлите на екипа на проекта** и по няколко писма на час. Всеки друг се регистрира, писмо не идва, а входът отговаря „имейлът не е потвърден“. |
| **Схема на базата** (`supabase/schema.sql`) | ❌ никога не е пускана | `profiles`, `settings`, `subscriptions`, … не съществуват (HTTP 404). До тази поправка engine-ът четеше `profiles` веднага след входа, получаваше 404 и **входът се проваляше** дори с правилна парола. |
| **Edge Functions** (`account`, `ai-fix`, `billing`, `monitor`, `admin`) | ❌ нито една не е качена | Без тях няма AI в облака, планове, покупки, облачен мониторинг, експорт/изтриване на акаунт, admin панел. |
| GitHub / Apple вход | изключени | Показват се само бутоните, които облакът наистина поддържа. |

Това са еднократни стъпки на собственика. Приятелите и клиентите после само се регистрират.

## Какво вече е поправено в приложението (без да пипаш облака)

- Входът минава дори когато схемата липсва: получаваш профил по подразбиране (Free) и предупреждение
  „Влезе, но облакът не е довършен“, вместо грешка.
- Екранът за вход има **„Не можеш да влезеш? Провери облака“** — показва точно кое липсва (схема, функции,
  регистрация, потвърждение на имейл) с бутон към Supabase dashboard и към Настройка → Облак.
- При „имейлът не е потвърден“ има бутон **„Изпрати потвърждението отново“**.
- **Настройка** има нова първа група **„Облак“**: проект, схема (копира я и отваря SQL Editor), функции,
  регистрация, потвърждение на имейл — със същите проверки като `bid cloud doctor`.
- Всяка липсваща функция дава една ясна грешка `cloud_function_missing` вместо „HTTP 404“.
- „Продължи без акаунт“ работи както преди — проверки, deploy и локален мониторинг не зависят от облака.

## Път А — всичко от GitHub с един токен (препоръчан, ~5 минути)

1. Supabase → долу вляво аватар → **Account → Access Tokens → Generate new token** (име например
   `beforeideploy-deploy`). Копирай го веднага — показва се само веднъж.
2. GitHub → хранилището → **Settings → Secrets and variables → Actions → New repository secret**:
   име `SUPABASE_ACCESS_TOKEN`, стойност — токенът. (Никой в кода не го вижда; workflow-ът не го печата.)
3. GitHub → **Actions → cloud-deploy → Run workflow**, клон `claude/nifty-edison-1195gi`. Опции:
   - `apply_schema` ✅ — пуска `supabase/schema.sql` (може многократно, всичко е idempotent);
   - `deploy_functions` ✅ — качва петте функции (`billing` и `monitor` без verify-jwt, както в README-то);
   - `disable_email_confirmation` — **включи го**, ако няма да настройваш SMTP: иначе никой освен екипа
     на проекта не може да завърши регистрация;
   - `allow_app_redirect` ✅ — позволява `beforeideploy://auth-callback` за GitHub/Apple вход по-късно.
4. Последната стъпка на workflow-а пробва проекта отново и печата таблица: всички таблици 200, всички
   функции ≠ 404. Същото виждаш и в приложението: вход → „Провери облака“ или Настройка → Облак.

Токенът дава пълен достъп до проектите ти в Supabase. Ако не искаш да стои в GitHub — изтрий secret-а след
успешния run (workflow-ът е нужен само при промяна на схемата или функциите).

## Път Б — на ръка в Supabase dashboard (~15 минути)

1. **Схема**: в приложението Настройка → Облак → „Копирай схемата и отвори SQL Editor“ (или
   `supabase/schema.sql` от хранилището) → постави → **Run**. Може да се пуска повторно.
2. **Функции**: с Supabase CLI на Mac-а —
   ```
   supabase login
   supabase link --project-ref rrnveotqvmsspmzaswlp
   supabase functions deploy admin ai-fix account
   supabase functions deploy billing --no-verify-jwt
   supabase functions deploy monitor --no-verify-jwt
   ```
3. **Потвърждение на имейла**: Authentication → Providers → Email → изключи **Confirm email**
   (или Project Settings → Authentication → SMTP Settings → собствен SMTP, напр. Resend, и остави
   потвърждението включено; шаблоните са в `supabase/email-templates/`).
4. **Redirect за OAuth** (по желание): Authentication → URL Configuration → Redirect URLs →
   `beforeideploy://auth-callback`.

## Какво остава само за теб и в двата пътя (тайни — никога от CI)

- `supabase secrets set ANTHROPIC_API_KEY=…` — AI в облака (`ai-fix`).
- `supabase secrets set PADDLE_API_KEY=… PADDLE_WEBHOOK_SECRET=… PADDLE_ENV=sandbox` — планове и покупки.
- `supabase secrets set MONITOR_CRON_SECRET=<дълъг случаен низ>` и после `supabase/monitor-cron.sql` в SQL
  Editor (двата placeholder-а) — облачният scheduler за мониторинг.

Без тези тайни входът, профилът, планът Free, локалните проверки, deploy и мониторингът на Mac-а работят;
функциите отговарят с ясна грешка `not_configured`, когато липсва тяхната тайна.

## Как да провериш, че всичко е наред

- GitHub → Actions → **cloud-check** → Run workflow: печата health, auth настройки, таблици и функции.
- В приложението: екран за вход → „Провери облака“; или Настройка → група „Облак“ (всичко зелено, освен
  „Потвърждение на имейла“, което е по избор).
- От терминал на Mac-а: `~/Library/Application\ Support/BeforeIDeploy/engine/bid cloud doctor`.

## Ако входът пак не минава

| Съобщение | Причина | Какво да направиш |
|---|---|---|
| „Грешен имейл или парола“ | точно това | „Забравена парола?“ праща писмо (важи същото ограничение за mailer-а) |
| „Имейлът не е потвърден“ | писмото не е стигнало | бутон „Изпрати потвърждението отново“; собственик: изключи Confirm email или сложи SMTP |
| „Не мога да достигна сървъра на акаунтите“ | няма мрежа / проектът е паузиран (безплатните проекти спират след неактивност) | Supabase dashboard → Restore project |
| „Влезе, но облакът не е довършен“ | схемата липсва | Път А или Б, стъпка 1 |
| `cloud_function_missing` | функцията не е качена | Път А или Б, стъпка 2 |
