готови за пускане плащания.

## 2. Решения за архитектурата (препоръка + проверка с прототип преди голямото писане)

| # | Решение | Препоръка | Защо | Проверка (Фаза 1) |
|---|---|---|---|---|
| A1 | Един интерфейс за уеб и компютър | **TypeScript + React + Vite** в `web/`; дизайн токените от V12 стават CSS променливи | един код за 3 платформи; V12 токените вече са семантични | прототипът минава на Chrome/Safari/Firefox/Edge и в Tauri на Mac и Windows |
| A2 | Обвивка за компютър | **Tauri 2** (тънко Rust ядро) + engine като **sidecar** (вграденият Node runtime, който вече имаме) | малък инсталатор, системен WebView, подписан updater, keychain през `keyring` | Spike P1 (§4) на macOS 14/15 и Windows 11 |
| A3 | Връзка интерфейс ↔ engine | нов режим `bid serve --stdio` (JSON-RPC 2.0, същите NDJSON събития като днес); CLI остава | един договор за desktop и за облачния runner | договорни тестове: едни и същи заявки към локален engine и към runner |
| A4 | Уеб работи с код | **Git проект** (GitHub App с достъп само до избраните repo-та; GitLab по-късно) + **облачен runner** в изолирана среда | браузърът не може да пуска npm/build; File System Access API е ограничен и не е навсякъде | Spike P2 (§4) |
| A5 | Облачен runner | краткоживеещи изолирани машини (кандидати: Fly.io Machines / Firecracker-базиран доставчик; решение в ADR след spike) — един job = една машина, без мрежов достъп до вътрешните ни услуги, лимит време/CPU/диск | сигурност (чужд код), цена на минута | spike мери: старт < 15 s, цена/минута, убиване при таймаут, липса на изтичане между jobs |
| A6 | Общ облак | Supabase остава: акаунти, сайтове, планове/кредити, jobs, история, наблюдение, архиви (Storage) | вече е изграден и тестван (RLS, SQL функции) | — |
| A7 | SwiftUI приложението | **поддържа се (само поправки)** до врата G2; после се заменя с Tauri версията | не пренаписваме, преди новото да има паритет | G2 = паритет по чеклиста в Фаза 9 |
| A8 | Архиви | **собствени архиви** вместо CodeGuard: git bundle на кода + публикуваният артефакт + конфигурация на доставчика, криптирани в Storage; възстановяване = повторно публикуване на артефакта | CodeGuard няма публично API/партньорство; за статични/Jamstack сайтове артефактът е пълното състояние | тест: изтриваме сайта при доставчика → възстановяваме от архив → същият SHA-256 манифест |
| A9 | Хостинг от нас | Flash/High: **твой хостинг** (свързан акаунт). Knight: **хостинг от нас** в Netlify екипа на собственика — само след писмено разрешение от Netlify (флаг) | честно обещание; без договорка не продаваме чужд ресурс | врата G3 |

Всяко решение се записва като ADR в `docs/adr/NNN-*.md` (контекст, варианти, решение, последствия).

### Фаза 3 — Един напълно работещ сценарий (golden path), уеб + Mac

(preview) → публикуване на живо → домейн → наблюдение → сигнал за проблем → възстановяване → покупка на кредити / смяна на
план (sandbox).**

- Без истински ключове в repo-то; тайните — само като secrets/Keychain/Credential Manager.

- Engine остава без npm зависимости; `web/` и Tauri имат lockfile и проверка за уязвимости в CI.
- Нищо не се смята за готово без доказателството от таблицата; при неуспех — честно в резюмето.
