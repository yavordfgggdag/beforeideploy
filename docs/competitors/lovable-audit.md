## Lovable Cloud (11)

### Lovable Cloud (built-in backend)

Built-in backend enabled by default on every project: isolated PostgreSQL database, authentication, file storage, Edge Functions, scheduled jobs, secrets, logs, usage and AI, running on the Supabase open-source stack but fully managed by Lovable (launched Sept 2025 after acquiring Molnett). Each project gets a separate Supabase project with its own DB, Auth, Storage, Edge Functions and API endpoints; data encrypted AES-256 at rest, TLS 1.3 in transit; protected by WAF, network isolation and adaptive rate limiting.

- **Как се ползва:** Enabled automatically on new projects. Open More → Cloud in the project toolbar to reach Overview, Database, Users, Storage, Functions/Edge functions, Jobs, Secrets, Logs, Usage, AI and Advanced settings. Ask for backend features (tables, login, uploads) in the project chat and Lovable builds them against Cloud.
- **Ограничения / план:** 20-credit monthly Cloud grant on Free, Pro and Business; further Cloud usage draws from the unified credit balance (usage-based: instance size, uptime, traffic, DB storage, network, file storage, compute, realtime). Enterprise has its own terms.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/cloud · https://docs.lovable.dev/integrations/cloud · https://lovable.dev/blog/lovable-cloud

### Database view (Cloud → Database)

Browse tables and views with row counts, open a table to an editable records grid (double-click a value to edit inline), run SQL in the SQL editor, review RLS policies, and restore daily backups.

- **Как се ползва:** More → Cloud → Database. Click a table to view/edit records; use the SQL editor area to run queries; sub-sections for RLS policies and Backups.
- **Ограничения / план:** Available on all plans with Cloud enabled. RLS policies view is read-only (change policies via chat).
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/database · https://docs.lovable.dev/features/cloud

### Database Backups (daily restore)

Restore the Cloud project database (schema and data) to any recent daily backup in a few minutes without contacting support.

- **Как се ползва:** More → Cloud → Database → Backups, choose a daily backup and confirm restore.
- **Ограничения / план:** Recent daily backups only; exact retention window not stated in the search summaries.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/database · https://docs.lovable.dev/features/cloud · https://docs.lovable.dev/changelog

### Storage (Cloud → Storage)

File storage in buckets. Each bucket card shows name, last updated and Private/Public. Private (default) is governed by RLS; Public is accessible to anyone with the URL. Upload (multi-file, drag and drop), download (multiple as zip), rename, delete, folders, file details with preview for image/video/audio, Copy URL (permanent for public, 1-hour signed URL for private).

- **Как се ползва:** More → Cloud → Storage. Create a private or public bucket, upload files, click a file for details and Copy URL. Storage files for migration are downloaded from here.
- **Ограничения / план:** Public storage buckets are blocked by default on all plans; a workspace owner/admin can disable the block in Privacy & security. Storage files are not included in database export.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/storage · https://docs.lovable.dev/features/advanced-settings · https://docs.lovable.dev/tips-tricks/external-deployment-hosting

### Edge functions

Server-side functions (Supabase Edge Functions) for payments, emails, AI, scheduled tasks and external API calls. Lovable writes, deploys and maintains them from chat; each function has a View logs action that opens Logs filtered to that function, with error output per failed invocation.

- **Как се ползва:** Describe the backend need in chat; Lovable creates and deploys the function. Inspect under More → Cloud → Functions (Edge functions) and click View logs.
- **Ограничения / план:** Compute counts toward Cloud usage credits. Also works against your own connected Supabase project.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/edge-functions · https://docs.lovable.dev/integrations/cloud · https://docs.lovable.dev/integrations/supabase

### Jobs (scheduled / cron tasks)

Scheduled background tasks for recurring work (sync data, post updates, checks). Jobs tab lists every job with status, plain-language schedule (e.g. 'Every day at 08:00 AM', 'Every 15 minutes') shown in your timezone, last run and run history; enable/disable without leaving the page.

- **Как се ползва:** Ask in chat to schedule a task; manage under More → Cloud → Jobs. Cron task logs appear in Logs.
- **Ограничения / план:** Runs consume Cloud compute credits.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/jobs · https://docs.lovable.dev/features/logs

### Logs

Searchable backend logs across Server, Function edge logs (request/response), Authentication, PostgreSQL, Realtime and scheduled job/cron executions; records requests, function output, DB activity, sign-ins and errors.

- **Как се ползва:** More → Cloud → Logs; filter by type, relative time range, or absolute start/end; or click View logs on a function.
- **Ограничения / план:** Relative ranges go back up to 5 days; older windows via absolute times; long-term retention requires your own logging.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/logs · https://docs.lovable.dev/features/edge-functions

### Advanced settings (resource health, Manage instance)

Infrastructure page for Cloud: resource health, Database size row with Manage → Manage instance dialog to resize compute (each size shows Estimated cost in monthly Cloud credits based on last 30 days usage or a default estimate); Database storage row with Increase database storage; Export project data; Pause Cloud; Remove Lovable Cloud. You can also ask in chat to resize the instance.

- **Как се ползва:** More → Cloud → Overview → Advanced settings. Click Manage next to Database size, pick a size, confirm.
- **Ограничения / план:** Larger instances use more credits per hour. Estimated cost visible to editors, admins, owners on all plans. DB storage minimum 8 GB, increase-only, up to four changes per 24 hours.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/advanced-settings · https://docs.lovable.dev/changelog

### Pause Cloud / Remove Lovable Cloud

Pause Cloud suspends database, auth, storage and Edge Functions to save credits and can be resumed anytime. Remove Lovable Cloud permanently deletes the Cloud instance (irreversible).

- **Как се ползва:** More → Cloud → Overview → Advanced settings → Pause Cloud → Pause → confirm; or Remove Lovable Cloud after exporting data and downloading files.
- **Ограничения / план:** Removal cannot be undone.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/advanced-settings

### Realtime (live updates)

Realtime updates (Supabase Realtime) available in Cloud, governed by RLS; appear as a Realtime usage category and Realtime log type.

- **Как се ползва:** Ask in chat for live-updating data; monitor under Cloud → Usage and Logs.
- **Ограничения / план:** Counts toward Cloud credits.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/project-usage · https://docs.lovable.dev/features/logs · https://docs.lovable.dev/features/database

### Cloud reliability / status page

status.lovable.dev publishes incidents, several tied to upstream Supabase (project creation failures, remix/management API); StatusGator counts 400+ detected incidents in a year.

- **Как се ползва:** Check status.lovable.dev.
- **Ограничения / план:** n/a
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://status.lovable.dev/history · https://status.lovable.dev/incidents/01JXJPHSXAVQWQRJS04VBPCZ0Y · https://statusgator.com/services/lovable

## Credits (8)

### Daily chat allowance ('Chat for free')

Free, Pro and Business workspaces include a daily chat allowance that covers Chat mode messages, Chats (outside a project), voice conversations and Lovable-in-Slack messages before credits are touched. The allowance has no fixed message count: each message consumes an amount based on the work required. Pro and Business receive a larger allowance than Free. While it lasts the dashboard's send button reads 'Chat for free'.

- **Как се ползва:** Use Chat mode / Chats; nothing to enable. Allowance usage is automatic.
- **Ограничения / план:** Resets daily at 00:00 UTC, does not roll over; Pro/Business larger than Free; pricing model guaranteed through 31 Oct 2026. Enterprise not mentioned.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/chat-mode · https://docs.lovable.dev/introduction/credits-and-usage · https://lovable.dev/blog/chat-for-free

### Per-message cost visibility (no upfront estimate)

Lovable does not show an estimate before a Build run because cost depends on work discovered during execution; the exact deduction is shown afterwards (and live during the run) under 'Credits used' in the More options menu. In 2025 the same figure was shown by hovering the three dots under a message.

- **Как се ползва:** Open More options under any response → read Credits used.
- **Ограничения / план:** Build: usage-based (examples 0.50–2.00 credits). Plan: 1 credit + subagents. Chat: fraction of a credit after allowance. Credits are non-refundable; if a prompt fails with an internal error before processing, credits are typically not deducted—contact support with error ID and timestamp otherwise.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/introduction/credits-and-usage · https://lovable.dev/blog/agent-mode-beta · https://lovable.dev/faq/ai-agent/errors/credits-lost-internal-error

### Image/video generation usage reporting

Workspace settings → Plans & credit usage → Usage details lists 'Image generation' and 'Video generation'; per-message 'Credits used' and 'Worked for' shown in a response's More options menu.

- **Как се ползва:** Workspace settings → Plans & credit usage → Usage details.
- **Ограничения / план:** None.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/changelog · https://docs.lovable.dev/features/projects/chat

### Credits (one credit balance)

The single metering unit. Lovable is rolling out one balance covering three usage types: Build (Plan and Build mode messages, edits, generation, investigation, verification), Cloud (database server, storage, compute, network, realtime) and AI gateway (runtime AI in deployed apps). Usage-specific grants are consumed before general (paid) credits. Credit value and burn rate depend on plan and feature.

- **Как се ползва:** Credits are deducted automatically; view the balance in Settings -> Plans & credit usage.
- **Ограничения / план:** Some workspaces may still see the older separate Cloud/AI balance view during the rollout.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://github.com/cporter202/lovable-for-beginners/blob/main/supplement-pricing-and-plans.md · https://github.com/joycaption/lovable-pricing · https://docs.lovable.dev/introduction/credits-and-usage

### Daily build credits

A free grant of 5 build credits every day on Free, Pro and Business. Reset at 00:00 UTC; unused daily credits do not roll over. On Free (and some regional plans) the grant is capped at 30 credits per month.

- **Как се ползва:** Automatic; shown as a separate grant in Plans & credit usage.
- **Ограничения / план:** Expire at end of day. Free: stops after 30/month and resumes next calendar month.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://github.com/cporter202/lovable-for-beginners/blob/main/supplement-pricing-and-plans.md · https://github.com/scrape-creators/lovable-pricing-examples · https://github.com/joycaption/lovable-pricing

### Monthly Cloud grant

20 Cloud credits per month on Free, Pro and Business to cover running deployed apps on Lovable Cloud (hosting, database, storage, compute). Beyond the grant, Cloud usage draws from the paid balance.

- **Как се ползва:** Automatic once a project uses Lovable Cloud and is published.
- **Ограничения / план:** Described by Lovable as temporary and subject to change. Spent before general credits.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://github.com/cporter202/lovable-for-beginners/blob/main/supplement-pricing-and-plans.md · https://github.com/kimi-cli/awesome-lovable-pricing · https://github.com/joycaption/lovable-pricing

### Monthly AI grant

4 credits per month for in-app AI features (Lovable AI / AI gateway) on Free, Pro and Business, letting builders try runtime AI without a provider key.

- **Как се ползва:** Automatic; consumed when deployed apps call Lovable AI.
- **Ограничения / план:** Temporary grant per Lovable; after it is used, AI gateway usage draws on general credits.
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://github.com/cporter202/lovable-for-beginners/blob/main/supplement-pricing-and-plans.md · https://github.com/kimi-cli/awesome-lovable-pricing · https://docs.lovable.dev/features/ai

### Credit rollover and expiry rules

Paid monthly plan credits roll over while the subscription stays active but expire two months after issue. Annual-plan credits expire one month after the annual period ends. Top-up credits expire 12 months after purchase. Daily build grants expire at end of day.

- **Как се ползва:** Expiry dates are shown in Settings -> Plans & credit usage.
- **Ограничения / план:** Rollover only on paid plans (Pro/Business).
- **Увереност:** medium · статус: непотвърдено
- **Източници:** https://github.com/cporter202/lovable-for-beginners/blob/main/supplement-pricing-and-plans.md · https://github.com/scrape-creators/lovable-pricing-examples · https://github.com/joycaption/lovable-pricing

## Visual editing (6)

### Preview toolbar – Select elements

Point-and-describe editing: select one or more elements in the live preview; each becomes a reference chip in the chat input and a short plain-language prompt (e.g. 'Make this the primary color') is applied to all of them. Replaces the former Visual Edits panel.

- **Как се ползва:** Click 'Select elements' in the preview toolbar or press S → click an element; Cmd/Ctrl+click to add more → type the change in chat → send.
- **Ограничения / план:** Uses credits like any chat edit.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/design · https://docs.lovable.dev/features/preview-toolbar

### Preview toolbar – Edit text inline

Fix typos or change wording directly in the preview without a prompt.

- **Как се ползва:** Preview toolbar → Edit text inline mode → click text → type → save.
- **Ограничения / план:** Text-only changes.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/preview-toolbar

### Preview toolbar – Draw annotation

Draw on the preview to show a layout or spatial change that is hard to describe; the annotated screenshot is sent with the prompt.

- **Източници:** https://docs.lovable.dev/features/preview-toolbar

### Preview toolbar – Add a comment

Leave feedback pinned to the preview for yourself or teammates.

- **Как се ползва:** Preview toolbar → Add a comment → click location → type.
- **Ограничения / план:** None documented.

### Preview toolbar placement and theme (Auto/Light/Dark)

Toolbar docks bottom-center, snaps to corners, can be dragged anywhere, minimized to an edge tab, hidden and restored from the project toolbar options; its own appearance can be pinned to Auto (adapts to background), Light or Dark.

- **Как се ползва:** Drag the toolbar; options menu → Auto/Light/Dark; project toolbar options → show/hide toolbar.
- **Ограничения / план:** None.

## Integrations (6)

### Connectors catalog (app + chat connectors)

Catalog at lovable.dev/connect of gateway-managed connectors usable both in project chat and in published apps, grouped by category (Business & CRM, Commerce & payments, Communications, Maps & media, AI & automation, Cloud). Examples: Stripe, Shopify, WooCommerce, HubSpot, Salesforce, Airtable, Slack, Twilio, Google Maps Platform, Google Workspace (Gmail, Calendar, Drive, Sheets, Slides), Gemini Enterprise, Microsoft 365, GitHub API, LinkedIn, Snowflake, BigQuery, Databricks, Workday, AWS S3, AWS API, Azure Cloud API, Azure Graph & Entra API, Google Cloud API, Looker, Cloudflare API, Firebase Cloud Messaging, Google Search Console, Perplexity, ElevenLabs, Firecrawl, Apify, Parallel, Inngest, Replicate, Gemini, Miro.

- **Как се ползва:** Connectors panel → browse catalog → Connect once (OAuth or API key) → ask Lovable to use it; the gateway handles auth and token refresh.
- **Ограничения / план:** Connector usage can consume credits ('connector usage' is a credit category); provider billing applies (e.g. Inngest, Apify bill on their side).
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://lovable.dev/connect · https://docs.lovable.dev/integrations/introduction · https://docs.lovable.dev/changelog

### Chat connectors (MCP servers)

MCP-based connectors that give the Lovable agent context while building: Linear, Notion, Confluence, Jira, n8n, Wispr Flow, Granola, Miro, Sentry, Hex, Confidence, PostHog, Polar, Sanity; Figma Desktop and Paper via local MCP in the desktop app; any other tool via Custom MCP server.

- **Как се ползва:** Connectors → Chat connectors → connect (OAuth) → reference the tool in chat (e.g. 'build from this Notion PRD'). Custom: add the MCP server URL/credentials.
- **Ограничения / план:** Local MCP servers (Figma Desktop, Paper) require the Lovable desktop app.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/integrations/mcp-servers · https://docs.lovable.dev/integrations/custom-mcp · https://lovable.dev/blog/mcp-servers

### App user connectors

Let each end user of a published app connect their own third-party account (Google Gmail/Calendar/Drive/Docs/Sheets/Slides, Microsoft Outlook/OneDrive/SharePoint/Teams/OneNote/Office, GitHub, GitLab, Slack, Salesforce, HubSpot, Linear, Notion, Databricks, Microsoft Fabric, Snowflake, Amazon Redshift, Workday) so the app acts with their permissions; tokens stored encrypted in the connector gateway per user.

- **Как се ползва:** Builder registers an OAuth client with the provider once per workspace and adds it to the connector client; users go through the provider's OAuth consent in the published app.
- **Ограничения / план:** Requires registering your own OAuth application for some providers (Salesforce External Client App, Databricks OAuth app, Snowflake security integration).

## Custom domains (5)

### Custom domains (Settings > Domains)

Connect a domain you already own to a published project. Lovable supports apex domains, www and other subdomains; multiple domains can point to one project; one domain belongs to one project at a time; domains can be removed or moved to another project. SSL is provisioned automatically after DNS is verified.

- **Как се ползва:** Project -> Settings -> Domains -> 'Connect domain' -> enter the domain -> either use the automatic Entri flow or follow the manual DNS instructions (A record for @ and for www pointing at Lovable's IP, plus a TXT verification record) -> wait for verification (minutes to 72 hours for DNS propagation) -> Update the published site.

## API / SDK (5)

### Lovable Public API v1 and Access tokens (API keys)

REST management API at api.lovable.dev (OpenAPI at https://api.lovable.dev/v1/openapi.json). Keys are created in workspace settings at lovable.dev/settings/api-keys on the 'Access tokens' tab, scoped to one workspace, with Read-only or Full access per resource (`projects:read/write`, `workspaces:read/write`). Operations: `GET /v1/me`, list workspaces, list projects (cursor pagination, limit 1–100), get project, create embed URL, publish project, poll deployment, update publish audience, delete publish (take offline). Standard error envelope with `type`, `request_id`; rate-limit headers.

- **Как се ползва:** Workspace admin/owner: Settings > API keys > Access tokens > create key, choose resources and access level; call with `Authorization: Bearer`.
- **Ограничения / план:** Workspace must be on Business plan or higher (lower plans get `402 payment_required`); two operations (project PII labels, Security Center project inventory) require Enterprise. Rate limits: publishing 10/min, deployment polling 120/min, analytics / security-center insights / collaborator reads 300/min.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://www.npmjs.com/package/@lovable.dev/sdk

### @lovable.dev/sdk (TypeScript SDK)

Official TypeScript SDK (`npm install @lovable.dev/sdk`, v8.0.1, first published 2026-01-21) wrapping the public API: `LovableClient`, `me()`, `listWorkspaces()`, `listProjects()`, `getProject()`, `createEmbedUrl()`, typed openapi-fetch client (`client.typed`), `ApiError` with retry on 429. Marked 'experimental software' with no stability guarantee. It also exposes non-public builder operations (`createProject`, `remixProject`, `chat`, `listMessages`, `waitForMessageCompletion`, `createVariant`, database, git and file access, uploads, knowledge, skills, connectors, folders) that reject settings-page keys with `403 audience_forbidden`.

- **Как се ползва:** `const client = new LovableClient({ apiKey }); await client.listProjects(workspaceId)`.
- **Ограничения / план:** Business+ plan for public v1; builder operations need a non-public key and are undocumented.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://www.npmjs.com/package/@lovable.dev/sdk

### Embed URL (preview without login)

`POST /v1/projects/{id}/embed-url` returns a preview URL valid for one hour and bound to one exact HTTPS parent origin, so visitors can view the built preview inside another site without a Lovable login.

- **Как се ползва:** Call via SDK `client.createEmbedUrl(projectId, parentOrigin)` with a `projects:write` key; iframe the returned URL.
- **Ограничения / план:** Business or higher and edit permission on the project.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://www.npmjs.com/package/@lovable.dev/sdk

### Publish via API and deployment polling

`POST /v1/projects/{id}/publish` returns 202 with a Deployment (`running`); poll `GET .../publish/{deployment_id}` until `completed` or `error`; `PATCH .../publish` changes `audience` (e.g. `workspace`) and `audience_targets` without redeploying; `DELETE` takes the app offline. Project GET exposes `is_published`, `publish_audience`, `publish_audience_targets`.

- **Как се ползва:** See SDK README sample: publish, then poll no more than once every 2 seconds, give up after a deadline.
- **Ограничения / план:** Publishing limited to 10/min, polling 120/min; Business+.

## Project chat – modes (3)

### Mode picker (Build / Plan / Chat)

The project chat has three modes selected from a mode picker beside the chat input: Build (changes the app directly; the default), Plan (investigates and writes a plan you edit and approve before any code is written) and Chat (discusses the open app without changing code). One conversation carries across all three modes, so you can switch at any time without losing context. The dashboard prompt box opens in Build the first time and then remembers the mode you last used.

- **Как се ползва:** Open a project; in the chat input area click the mode picker and choose Build, Plan or Chat; type or dictate your message and send. Switch modes at any time; the thread continues.
- **Ограничения / план:** Build mode is usage-based (often <1 credit); Plan mode = 1 credit + any subagent research; Chat mode = fraction of a credit, covered first by the workspace's daily chat allowance.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/features/projects/chat · https://docs.lovable.dev/features/chat-mode · https://docs.lovable.dev/features/plan-mode

### Plan mode and the Plan view

Plan mode investigates the project (files, database, logs) across multiple steps, asks clarifying questions, and writes a structured plan that opens in the Plan view as a readable rich-text document (read and edit in one view). You can edit the plan text directly, or highlight any part of it and describe what should change—Lovable edits only that section and shows the revision as a diff (removed wording struck through, new wording highlighted). While in progress the plan lives at .lovable/plan.md; on approval it is moved into .lovable/plan/ as a dated file. Approving switches to Build mode and implementation runs from the approved plan until complete. Plan mode never modifies code.

- **Как се ползва:** Choose Plan in the mode picker → describe the feature/bug → answer any clarifying questions → review the plan in the Plan view → edit inline or highlight+describe changes → click approve to start building.
- **Ограничения / план:** 1 credit per Plan mode message plus usage-based cost of any subagent research; larger/open-ended requests can cost more than 1 credit.

Chat mode discusses the open app without changing code or data: ask how something works, explore an idea, debug, decide what to change. ## Prompt tips (2)

## Project chat – errors (1)

### Try to fix

When a build error appears while Lovable works (or the preview goes blank), a 'Try to fix' button appears on the activity card. Clicking it makes Lovable scan logs, find the issue and attempt a fix. Each account has 10 free fixes shared between 'Try to fix' and 'Try to fix all' in the Security view, across all workspaces and projects; each free fix becomes available again 24 hours after use. After the 10 are used, Try to fix still works but is billed as standard Build usage. Docs advise: if 2–3 attempts fail, switch to Plan mode and ask Lovable to investigate the root cause rather than retrying. Third-party reviews describe 'fix loops' where repeated attempts stack half-applied patches and burn credits.

- **Как се ползва:** Click 'Try to fix' on the error card; if it recurs, switch to Plan mode and describe what you see vs. expected, or revert via History.
- **Ограничения / план:** 10 free fixes per account (rolling 24h refresh each); then credits.
- **Увереност:** high · статус: непотвърдено
- **Източници:** https://docs.lovable.dev/tips-tricks/troubleshooting · https://docs.lovable.dev/features/projects/chat · https://docs.lovable.dev/features/security-view

## Lovable Cloud / Config (1)

### Secrets

Injected automatically into Edge Functions, never reach the browser, never appear in code or repo. Write-only: once saved the value can only be replaced or deleted, not viewed.
