## 1. What the product is

**Before I Deploy** is a native macOS app (SwiftUI, macOS 13+) that checks a website project the way a careful
senior developer would before a release, explains problems in plain words (English / Bulgarian), proposes fixes
(deterministic "safe fixes" and AI patches), and publishes — draft first, production only after an explicit
confirmation and a fresh check of exactly the code on disk. It also watches live sites (uptime, SSL, domains),
tracks hosting costs, and offers optional accounts with paid plans for the built-in AI.

Three layers, one repository:

| Layer | Tech | Where | Size | Tests |
|---|---|---|---|---|
| App | SwiftUI, Swift Package, built with Command Line Tools only (no Xcode project) | `App/` | 9 855 lines, 36 files, 7 stores | 36 XCTest (`cd App && swift test`) |
| Engine `bid` | Node 18+ (22 in CI), **zero npm dependencies**, zsh launcher, NDJSON on stdout | `engine/` | 5 525 lines, 30 modules, 34 top-level CLI commands | 70 (`node tests/run.mjs`, Linux + macOS) |
| Cloud | Supabase: Postgres + RLS, 4 Deno Edge Functions | `supabase/` | schema 285 lines, 9 tables; functions 3 173 lines incl. tests | 68 Deno tests (`deno test supabase/functions`) |
| Website | static HTML generated by `scripts/site-build.py` | `site/` | 5 pages | screenshot-checked |

The app never talks to the network itself except to open URLs: **every action goes through the engine**
(`Process` → `bid …` → NDJSON events). The engine talks to Git, the hosting CLIs, Supabase and the AI providers.

### 1.1 Invariants (do not break — see also `AUDIT.md` §4, `ROADMAP.md` §10)

1. **Production deploy needs three things:** the literal confirmation `DEPLOY`, a check newer than
   `CHECK_MAX_AGE_MIN`, and the check's `fingerprint` equal to the current working tree (`netlify.mjs deployGuard`).
   The guard is in the engine, not only in the UI.
2. **Nothing is written to a user's project without consent:** safe fixes need `--yes`; AI patches are planned in
   memory and written only by `ai apply --yes`, all-or-nothing, never into `.git`, hooks, `node_modules`,
   package-manager config (`patch.mjs safePath`).
3. **Secrets never touch argv or logs.** Keychain writes go through `security -i` on stdin (base64), passwords go
   through env (`BID_PASSWORD`, `BID_AI_KEY`, `BID_ACCESS`), `engine.log` redacts argv, support reports are redacted
   (`aifix.mjs REDACTIONS`).
4. **Never `netlify init`** (it wires GitHub CI); we link/create sites through `netlify api`.
5. **The cloud is the source of truth for role / plan / credits**; the engine only turns them into feature gates
   (`features.mjs`); the app only renders.
6. **Money is idempotent:** every grant / refund / expiry has a `(user_id, ref, reason)` unique index; webhooks are
   claimed before processing; AI requests reserve credits before calling the model.
7. **All visible text is in the catalogs** (`App/Resources/*.lproj`, `engine/i18n/*.json`); `scripts/i18n-check.mjs`
   fails CI on a hard-coded string or a missing key. Every `EngineError` code is documented in `docs/errors.md`
   (`scripts/error-codes.mjs` fails CI otherwise).
8. **The engine ships inside the app** (`Contents/Resources/engine`); the app installs it into Application Support
   on launch; the app's own version (`CFBundleShortVersionString`) is what updates compare against.

## 3. Engine (`engine/`)

### 3.1 Launcher `engine/bid` (zsh)

Sources `env.zsh` (the user's Terminal PATH, captured by `install.sh`) **first**, then appends the usual install
places (`~/.volta/bin`, `~/.asdf/shims`, `/opt/homebrew/bin`, `/usr/local/bin`, bun, pnpm, …), resolves nvm's
default alias without loading `nvm.sh`, refuses Node < 18 and a missing Node with a JSON `result` line
(`code: "no_node"`, bilingual message), then `exec node src/bid.mjs "$@"`.

### 3.2 Protocol (NDJSON on stdout)

Every command prints zero or more event lines and exactly one final `result` line:

| type | fields | who reads it |
|---|---|---|
| `step` | `id, label, category, status (pending/running/pass/warn/fail/info/skipped), summary, details[], fixes[], log, duration, cached` | RunSession → run window |
| `log` | `step, line` | run window (batched, 600-line cap per step) |
| `info` | `message` | toast |
| `notify` | `title, body, url` | macOS notification |
| `ai` | `delta` (streamed answer text) | AIStore |
| `devicecode` | `code, url, service` | login flows (Netlify/GitHub) |
| `result` | `ok, data \| error, code, key, exit` | `EngineOutcome.decode` |

Exit codes: 0 ok · 1 error · 2 usage / missing confirmation · 3 blocked / no fresh check · 4 not linked · 5 not
logged in · 7 cloud not configured · 8 quota exhausted · 127 no node · 130 cancelled (SIGTERM/SIGINT/SIGHUP kill
every child, see `util.mjs children`).

Environment: `BID_LANG` (en/bg), `BID_CLIENT=app`, `BID_APP_DIR`, `BID_CACHE_DIR`, `BID_NO_KEYCHAIN`,
`BID_ENGINE` (app override), `BID_UPDATE_URL`, `BID_SUPABASE_URL/ANON_KEY`, `BID_NO_BUNDLED_CLOUD`,
`BID_PASSWORD`, `BID_AI_KEY`, `BID_ACCESS/REFRESH`, `BID_SPACESHIP_KEY/SECRET`.

### 3.3 State on disk

- `~/Library/Application Support/BeforeIDeploy/` — `projects.json` (library), `state/<key>.json` (per project:
  `check` incl. `fingerprint`, `stepCache`, `local` preview, `netlify`, `hosting`, `lastProd` sha), `history.json`,
  `profile.json` (cached cloud profile + settings), `update-cache.json` (6 h), `engine.log` (argv redacted),
  `logs/` (crash files), `secrets/` (0600 fallback only when `security` is absent, i.e. Linux tests).
- `~/Library/Caches/BeforeIDeploy/<project>/` — step logs, AI patch files, publish staging copies.
- Keychain service `BeforeIDeploy`, accounts: `session`, `spaceship`, `ai-anthropic`, `ai-openai` (values stored as
  `b64:<base64 JSON>`; older plain JSON still read).

### 5.2 Edge Functions (`handler.ts` testable, `index.ts` wires Deno.serve; tests use `_shared/fake_supabase.ts`)

- **`ai-fix`** (POST, user JWT): `{prompt, system?, step, project, mode fix|explain, deep}` → SSE stream of
  `delta / usage / done / error` events. Flow: profile → `expireDue` → `ensureMonthlyGrant` → plan gate (Free with
  top-up allowed) → input cap (`ai.promptMaxChars` + 8 000 for system) → balance → **reserve** (pending `ai_usage`
  row + `hold` ledger row for `(estInput + maxTokens) × multiplier`) → rate limits (`ai.rate` per minute/hour) →
  daily cap (`ai.dailyCapPercent` of monthly grant) → re-check balance including other holds → Anthropic Messages
  stream with `AbortController` (client cancel aborts upstream) → settle: delete hold, update usage, charge plan
  bucket first then top-up; on stream break bills an estimate from streamed characters. Codes: `no_profile`,
  `disabled`, `no_plan`, `prompt_too_long`, `quota_exhausted` (+`renewsAt`), `rate_limited`, `daily_cap`,
  `upstream`, `model_error`, `interrupted`, `not_configured`.
- **`billing`** (POST): user actions `catalog`, `status` (balances per bucket, subscription, `trialAvailable`, recent
  usage), `checkout --plan/--pack [yearly]` (Paddle transaction with `custom_data.user_id`), `trial` (trial_claims
  hash + unique trial subscription → 409 `trial_used`), `portal`. Webhook (`paddle-signature`, HMAC with several
  `h1`, 5-min skew): claim event first (duplicate → 200), `subscription.*` (highest tier among items, out-of-order
  events ignored by `event_at`, VIP/admin and manual plans keep their plan), `transaction.completed` (grant once
  per `txn` / `txn:price`, proration origins skipped, yearly = month 0 + lazy monthly grants `sub:mK`),
  `adjustment.*` refunds (proportional `share`, once per adjustment). Failure → claim removed → 500 → Paddle retries.
- **`account`** (POST): `export` (every row for the caller), `delete` (409 `subscription_active` when a Paddle sub
  cannot be cancelled here; cancels at Paddle, marks canceled, audit row with e-mail hash, deletes billing events,
  deletes the auth user → cascades).
- **`admin`** (POST, role admin): `list_users` (sanitized search, balances, last AI use), `get_user`, `set_role`,
  `set_plan_manual`, `grant_credits`, `disable_ai`, `get_usage`, `get_settings`, `set_settings` (whitelist
  `SETTINGS_KEYS`), `invite` (inviteUserByEmail, role, locale), `audit_log`. Every action is audited. All 500s are
  generic `{error:"internal error", code:"internal"}` (details in the function log).
- **`_shared`**: `db.ts` (`callerOf`, `json`, `readJson`, `must`, `isDuplicate`, `internalError`, `sha256Hex`),
  `credits.ts` (`bucketBalance`, `insertOnce`, `grantPlanTokens`, `ensureMonthlyGrant`, `expireDue`),
  `fake_supabase.ts` (in-memory PostgREST subset with unique indexes, write failures, derived balance views).

### 11.3 CodeGuard partnership — how to integrate without breaking the architecture

We do not know CodeGuard's API yet (owner to provide the repo or docs). The integration seams that already exist:

1. **As a check step.** Add `codeguard` to `checks.mjs STEPS` (category "Security") whose runner calls CodeGuard's
   CLI/API on the project and maps its findings to `step` details + `fixes` (safe fixes need `--yes`). If CodeGuard
   streams, forward lines as `log` events. Cache by `fingerprint` like lint/typecheck.
2. **As an AI-fix source.** CodeGuard findings can feed `aifix.mjs`/`ai/index.mjs` prompts (the log tail + the files
   the finding names, already redacted and fenced to the project).
3. **As a monitor signal.** In WP13 the monitor can poll CodeGuard for new vulnerabilities in deployed dependencies
   and raise `attention` items in Mission Control.
4. **As a plan feature.** A gate `security.codeguard` in `features.mjs` (Knight / maintenance plans) and a settings
   key `codeguard.*` (API base, plan mapping) in `SETTINGS_KEYS`.
5. **Shared account.** If CodeGuard has its own accounts, store its token in Keychain account `codeguard` via
   `secrets.mjs`; never in argv; add it to `REDACTIONS`.

Keep the invariants: CodeGuard can propose, only the user (or an explicit maintenance rule) applies.

## 12. Working rules for the next developer / Codex

- **Build without Xcode:** `cd App && swift build` (Command Line Tools). Use `@Local` not `@State`. Never add an
  `.xcodeproj`. macOS 13 API only (no `@Observable`, no `NavigationSplitView` tricks that need 14).
- **Every user-visible string** → `L("key")` (app) or `t()/msg()` (engine) in **both** `en` and `bg`. Add keys to
  both catalogs; `node scripts/i18n-check.mjs` must print `✅ i18n ok` (it also rejects English literals in
  `Text/Button/Label/title/help`).
- **Every new `EngineError` code** → a row in `docs/errors.md`; `node scripts/error-codes.mjs` must pass.
- **New engine command:** add the `case` in `bid.mjs`, a `help` line, a test in `tests/run.mjs` (use `t()`
  sync / `ta()` async, `mk()` temp projects, `bid()`/`bidEnv()`), a Swift model + fixture if the app reads it.
- **New cloud behaviour:** change `handler.ts`, add a Deno test against `FakeDb`, keep `deno check` clean, keep the
  schema migration idempotent (`create … if not exists`, `alter … add column if not exists`), verify with PGlite
  (`scratch: node check.mjs supabase/schema.sql` pattern in AUDIT batch 2).

  `sb_publishable_` anon key and public links.
- **Never** shadow `t` with a local variable in the engine (a test guards this).
- Commit per step with a descriptive message; CI must be green (`engine`, `engine-macos`, `app`, `functions`).
- Read `AUDIT.md` §4 and `ROADMAP.md` §10 invariants before touching deploy, secrets, billing or AI apply.
